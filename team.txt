HCLTech Amplified Hackathon — Round 2
AI-Powered Personalized Learning Path Recommender
TEAM ISSUE / FEATURE BREAKDOWN (Next.js + vanilla JS edition)
======================================================================

Stack: Next.js 14+ (App Router, JavaScript — no TypeScript), MongoDB
Atlas, Groq/Gemini free LLM API, deployed 100% on Vercel.

Team roles (assign real names against these slots as GitHub Assignees):

  M1 - Mahesh        -> Repo/Infra Lead + Auth + Profile API routes
  M2 - Member 2       -> AI Lead (LLM client, goal parsing, skill-gap,
                          recommendation, path generation, explanations)
  M3 - Member 3       -> Frontend: onboarding chat UI + auth pages
  M4 - Member 4       -> Frontend: roadmap visualization + dashboard
  M5 - Member 5       -> Data seeding + Progress/Milestone API routes +
                          deployment + docs/demo

ISSUE #1
Title: [Setup] Next.js app scaffolding + CI
Assignee: M1 - Mahesh
Description:
  Create the Next.js app with `create-next-app` (App Router, JavaScript,
  Tailwind CSS, ESLint, src/ directory). Set up folder structure:
  app/(pages), app/api/(route handlers), lib/, components/, models/.
  Add .env.local.example (MONGODB_URI, JWT_SECRET, GROQ_API_KEY,
  GEMINI_API_KEY). Add lib/mongodb.js with a cached MongoClient
  connection helper (required for serverless — avoid reconnecting per
  request). Add a GitHub Actions workflow that runs `npm run build` and
  `npm run lint` on every push/PR. Push incremental commits.
Labels: setup, priority-high

----------------------------------------------------------------------
ISSUE #2
Title: [API] Auth routes (JWT register/login)
Assignee: M1 - Mahesh
Description:
  Implement app/api/auth/register/route.js, app/api/auth/login/route.js,
  app/api/auth/me/route.js. Use bcryptjs for password hashing and
  jsonwebtoken for signing/verifying JWTs (stored as an httpOnly
  cookie). Store learners in a MongoDB "learners" collection. Add
  lib/auth.js with getSessionUser(request) helper for protected routes.
Labels: api, auth, priority-high

ISSUE #3
Title: [API] Learner profile routes
Assignee: M1 - Mahesh
Description:
  app/api/profile/route.js — GET (current learner's profile), POST
  (create), PATCH (update). Fields: interests[], experienceLevel,
  completedCourses[], careerGoal, learningStyle, timeframe. Persist to
  "learner_profiles" collection keyed by learnerId. Validate input
  with a simple manual validator or zod (JS, no TS needed).
Labels: api, priority-high

----------------------------------------------------------------------
ISSUE #4
Title: [Data] Course/resource catalog + seed script
Assignee: M5 - Member 5
Description:
  Write scripts/seedResources.mjs (plain Node script, run with
  `node scripts/seedResources.mjs`) that populates a MongoDB
  "resources" collection with 150-250 items across 4 domains (Web Dev,
  Data Science, DSA/Backend, Cloud/DevOps): {title, type, url,
  difficulty, topics[], estimatedHours, prerequisites[]}. Source from
  free resources (freeCodeCamp, MDN, roadmap.sh, official docs, known
  YouTube playlists). Also create lib/skillTaxonomy.js exporting a
  topic-prerequisite graph per domain, used by the skill-gap logic.
Labels: data, priority-high

----------------------------------------------------------------------
ISSUE #5
Title: [AI] LLM client wrapper
Assignee: M2 - Member 2
Description:
  lib/llmClient.js — a function `askLLM(systemPrompt, userPrompt,
  { jsonMode })` that calls the Groq chat completions REST API
  (model llama-3.1-8b-instant or similar free-tier model) via fetch,
  with GEMINI_API_KEY as a fallback provider if the Groq call fails or
  times out. When jsonMode is true, instruct the model to return only
  valid JSON, parse it, and retry once with a "return only valid JSON"
  correction message on parse failure.
Labels: ai-ml, priority-high

----------------------------------------------------------------------
ISSUE #6
Title: [API] Goal parser route (conversational onboarding)
Assignee: M2 - Member 2
Description:
  app/api/ai/parse-goal/route.js — POST {message, sessionId,
  knownFields}. Uses llmClient in jsonMode to extract {goal, domain,
  targetRole, experienceLevel, interests[], timeframe, missingFields[]}
  from free text, plus a natural-language followUpQuestion when fields
  are missing. Upsert partial profile fields to learner_profiles as
  they're extracted.
Labels: ai-ml, api, priority-high

----------------------------------------------------------------------
ISSUE #7
Title: [API] Skill-gap analyzer route
Assignee: M2 - Member 2

  completedCourses, goal}. Uses lib/skillTaxonomy.js to compute missing
